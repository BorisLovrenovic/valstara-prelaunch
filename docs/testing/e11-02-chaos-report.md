## Reproduction

Build the current application image and run the isolated, disposable drill harness:

```sh
docker build -t valstara-chaos:e11-02 .
node scripts/chaos/e11-02-run.mjs
```

The recorded rerun used `CHAOS_APP_PORT=54323 CHAOS_POSTGRES_PORT=55436` to avoid occupied local ports. The runner reads these optional overrides for both the Compose mappings and its own HTTP and PostgreSQL connections; omitting them uses the documented defaults.

The runner starts the production Compose services with `scripts/chaos/docker-compose.chaos.yml`, binds app and database ports to loopback, migrates a fresh database, executes the drills, records the result JSON, and removes its Compose project. The overlay adds a Node preload for controlled Cloudflare siteverify, Resend, and alert-webhook responses. These are simulated provider responses, while the application, PostgreSQL transactions, route handlers, email dispatcher, snapshot job, referral repair, flags, and webhooks are real local components.

**Drills 2, 4, 5 and 11 run through the production `maintenance` service** (QA gate 7, G7-1-I3). Its container runs the image's own command and its own `src/server` tree; the overlay gives it only the provider preload and the drill's state directory, and the runner asserts from `docker inspect` that nothing is mounted under `/app/src`. Drill 2 starts the worker with the Resend key revoked and waits on its own one-minute dispatch loop; drill 4 stops the worker, which owns the snapshot refresh, and starts it again; drill 5 restarts the worker so its scheduler runs the daily counter repair on its first cycle; drill 11 pauses the worker with `docker compose pause` and waits on the app's own heartbeat watchdog. The 2026-10-08 run had instead driven these jobs through one-shot scripts with `src/server` mounted from the checkout, and never started the worker, so it could not see that the image's worker failed to start (QA gate 7, G7-1-B1). The app keeps its source mount for the drill-6 flag one-shot. On the pre-fix image (`ghcr.io/local/valstara-prelaunch:prefix`, built from `main` at `e302654`), the re-run passes drill 1 and then fails drill 2: the maintenance container never becomes healthy. The preload prevents live provider sends. Drill 1 holds an after-insert trigger on a PostgreSQL advisory lock, observes the signup transaction waiting at that insert, and kills PostgreSQL before the transaction commits. All credentials and data are disposable; the result file contains no email addresses, raw IPs, tokens, or secrets.

Drill 6's removal time depends on where the app's five-second flag cache sits in its cycle when the flag changes; the image's own health check requests `/` every five seconds, which sets that cycle's phase. The first QA gate 7 re-run measured 1,047 ms; the two runs with the render cache measured 4,003 ms (an earlier build whose drill 11 assertion was wrong, see below) and 4,413 ms. All are inside the window, and a flag change gives the render cache a new key, so the cache adds no hold of its own (`test/render-cache.test.ts`). The first 2026-11-13 re-run's figures were 7,179, 63,766, 1,600, 306,004, 1,152, 7,318 (removal 1,047) and 827 ms for drills 1–6 and 8. The 2026-10-08 figures were 7,304, 5,408, 1,633, 303,722, 1,596, 7,148 (removal 941) and 643 ms for drills 1–6 and 8; drills 2 and 5 were faster then because one-shot jobs ran on demand rather than on the worker's schedule.

The first run of drill 11 failed its own assertion, not the system: it required the P1 more than 120 seconds after the pause, but the last beat lands up to one dispatch interval before the pause, so the watchdog correctly alerted 111,331 ms after it. The drill now asserts the alert's own `age_seconds`, which is the beat's age.

Verification replay may issue a fresh status-link token, so drill 8 excludes status-link tokens from the comparison. A temporary mutation advanced `verified_at` by one second after replay: the previous response-and-status check passed, while the new durable-state comparison failed. The mutation was removed before the passing run recorded above.

In the 2026-10-08 run, drill 4's regression check used a temporary application image that discarded snapshots older than 30 seconds. The strengthened drill failed at its HTTP status assertion (`503 !== 200`) after the five-minute hold. The cutoff was removed before the passing run above.

The original PostgreSQL attempt stopped the database during Turnstile verification and never reached the subscriber insert. The corrected failure point exposed an unhandled error event on a checked-out `pg` client: the app exited and reset the request. The database adapter now handles that event while the client is checked out and classifies the query failure as unavailable. Drill 1 then returned the matrix's HTTP 503 with no partial row after restart. No unresolved matrix deviation remained in the passing run.
