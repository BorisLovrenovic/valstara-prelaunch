**Finding A1 — the sticky bar cannot be reached by keyboard.** The bar (`[data-dock]` in `src/islands/SignupForm.astro`) follows the hero form in the document and shows only while the hero form is off screen. Tabbing forward past the hero brings the bar in, but focus is already below it. One Shift+Tab steps back to the catalogue and then into the hero, which scrolls the hero back into view and hides the bar again, so its field and Join button are never focused. The probe recorded this order, backward from below the hero at 390px: catalogue track, catalogue track (`bar=true`), catalogue track (`bar=false`), marketing checkbox, hero Join, hero email. The same signup is fully keyboard-operable through the header's Join link and the hero form, so this is not a loss of function under WCAG 2.1.1, but a keyboard user can never use the bar a pointer user sees. The fix changes where the bar sits in the island or the tab order, a design decision that is not recorded, so it is open for the founder.

**The spoken pass on the final design, 2026-11-13.** The same method as E11-03: Orca 46.1 with Speech Dispatcher and eSpeak NG, against headed Playwright Chromium 1.62.1 (`--force-renderer-accessibility`) in Xvfb, in a scratch container built from the pinned Playwright image with those packages added. The repository gained no dependency. The app ran from this branch's build against a disposable migrated database. Playwright's keyboard drove the page, with Turnstile's callback simulated and the signup responses answered in the browser, so no mail was sent and no subscriber was stored. Orca's `--debug-file` recorded, per action:

| Keyboard action | Spoken output |
|---|---|
| Tab to the hero email field | "Email address entry you@example.com required." |
| Tab to Join | "We'll email you a link to confirm your address." then "Join the waitlist push button." |
| Enter with the email empty | "Email address entry … required. invalid entry." then "We'll email you a link to confirm your address. Enter your email address." |
| Enter with a simulated rate limit | "notification." then the rate-limit message |
| Enter with a simulated invalid-email response | "invalid entry." then the hint and the error message |
| Enter with an accepted response | "Adding you to the waitlist…", then "Check your inbox heading level 2.", the echoed address, the next-step line and "Use a different address push button." |
| `/verify` with a link, Tab to the button | "Confirm email address push button." |
| Enter on an unknown link, then Tab through the request form | "Email address entry required." then "Request a new link push button." |

The speech was captured from a PulseAudio null sink's monitor, 64 s of 44.1 kHz two-channel PCM: −15.9 dB mean and 0.0 dB peak, so synthesis produced audio and not only log lines. The request form's empty-submit path was not exercised, because its button stays disabled until Turnstile's implicit widget answers, which the stand-in does not render; that form is native HTML (`required`, `type=email`), unchanged in behaviour by E11.5. The mobile sticky bar could not be spoken by keyboard, because focus never reaches it (finding A1).

**Finding L1 — the open security check overflowed the hero at 320px. Fixed.** The contact sheet's state `signup-08-security-check-visible` failed the layout checks at 320px in both themes: horizontal overflow, with the form, its section and `main` overflowing. Cloudflare's normal widget is a fixed 300px wide, the size `Hero.dc.html` draws, and the card's content box at 320px is narrower. The canvas has no 320px frame. `SignupForm` now asks Turnstile for its compact widget (150 × 140, the size the task pages already use) when the form's content box is narrower than 300px, and the normal widget otherwise. That is 320 and 360px; 390px and up keep the drawn widget. `test/landing-hero-rendered.test.mjs`, "the open Turnstile widget fits the form card at every design width", opens the widget at every design width and requires the size, the widget inside the form, no horizontal overflow and a clean layout check. It fails at 320px when the island always asks for the normal widget. The behaviour is unchanged: the same widget, token and callbacks.

**Finding E1 — email links are smaller than the 44px tap target. Open for a founder decision.** The contact sheet applies every layout rule to the email previews except the container grid. At 320, 360 and 390px every template's text links fall short of 44px: the footer's "Unsubscribe from Valstara email" (187 × 15) and each secondary link (116–170 × 17, or about 41px tall where a long label wraps, as in the winner email's rules link). The primary button is 44px, as E11.5-11 requires. E11.5-11 specified "secondary links as text" and required only buttons to be 44px tall, and design rule 8's enforced set is rendered pages, so the email layout does not break a rule it was built to. The site, though, makes every standalone link a 44px target below 48rem. Making the email links 44px rows changes E11.5-11's layout, which is the founder's call.
